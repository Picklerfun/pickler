# Future hourly breakout financial authority

This document describes the implemented, disabled configuration-v10 financial host. It does not
supply authorization, assign a start, allocate an operator, create accounts, or start a comparison.
The separately authorized 24-hour public source check remains nonfinancial. See
[the screen guide](PERPS-HOURLY-BREAKOUT.md) and
[the local host instructions](src/hourly-breakout/AGENTS.md).

## Independent authorization records

The committed configuration must retain `enabled: false`, `financiallyExecutable: false`,
`T0: null`, and `operator: null`. A future operator must supply a separate JSON file with format
`hourly-breakout-financial-authority-v1`. Its TypeScript contract is `FinancialAuthorityBundle`
in `src/hourly-breakout/financial-adapter.ts`. No example authority file is generated by prepare,
source acceptance, reports, tests, or this delivery.

The bundle contains:

| Field                  | Required meaning                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `configHash`           | SHA-256 of the exact configuration JSON projection.                                                                                                                  |
| `implementationCommit` | The clean, tested checkout used by the authorized future process.                                                                                                    |
| `acceptance`           | The trading-owned `BreakoutRunAcceptance`, including the future UTC-midnight `T0`, pre-start authorization date, named operator and separate acknowledgement hashes. |
| `technical`            | Relative or absolute file reference plus its exact byte SHA-256.                                                                                                     |
| `source`               | Compact source `acceptance.json` reference and exact byte SHA-256, plus `manifestFile` and the exact source-manifest byte `manifestSha256`.                          |
| `authorization`        | Separate operator financial authorization file reference plus exact byte SHA-256.                                                                                    |
| `clock`                | The separately accepted financial certificate and explicit source-local clock authority described below.                                                             |
| `resources`            | The frozen future local resource envelope described below.                                                                                                           |

`acceptance.protocolDigest` must equal the reviewed final protocol SHA-256 in the frozen
configuration, `36a06bef5267e7dc4407e78e508000e557da8df53e7df3f3f282cbe37e739816`.
This identifies the reviewed protocol. The configuration hash, implementation commit, catalog,
clock policy, `T0`, and role remain separately pinned. No replacement protocol namespace is inferred.

The technical file has format `hourly-breakout-technical-acceptance-v1`, `status: "PASS"`, and
matching `implementationCommit`, `configHash`, and `resourcesSha256`. Its byte hash must match
`acceptance.technicalAcceptanceSha256`. It must accompany the actual controlled test evidence;
a prepared configuration is not technical acceptance.

The compact source file must report `PASS_NONFINANCIAL_SOURCE_ACCEPTANCE`,
`financialAcceptance: false`, and external UTC as `UNVERIFIED`. The host also verifies the original
source manifest and replays the original complete source journals offline. A result label alone
is insufficient. The source commit must match the selected tested implementation. Source J
acceptance supplies no financial V authority.

The operator file has format `hourly-breakout-operator-financial-authorization-v1` and includes
`authorized: true`, the same configuration/implementation, `T0`, `operator.identity`,
`acknowledgementSha256`, `technicalAcceptanceSha256`, `sourceQualificationSha256`,
`clockPolicySha256`, and `resourcesSha256`. All references and byte hashes are checked before
reading the dedicated database file or constructing public data clients. An acknowledgement hash
is an explicit operator record, not a provider signature or a claim of external identity proof.

## Clocks and receipt evidence

`clock` declares `scope: "financial-valuation"`, `authority: "LOCAL_OS"`,
`externalUTC: "UNVERIFIED"`, `policyId`, `policySha256`, `epochId`, `certificateId`, and the complete
immutable `BreakoutClockCertificate`. Its ID must already appear in
`acceptance.acceptedClockCertificateIds`; scope, epoch, acceptance, numeric bounds, provenance,
and validity are checked. The validity interval must cover preflight through fixed `TF`.

`maximumBracketMs` and `maximumPairingDeviationMs` must be positive and at most 1,000. These are
finite local measurement limits, not an assertion about the machine's accuracy against external
UTC. Every actual boundary must fit the preaccepted certificate's bounds and validity. The
certificate is not rewritten after observing a slow, incompatible, or regressing clock.

The policy also contains this separately explicit `sourceAuthority`:

```json
{
  "scope": "source-local",
  "accepted": true,
  "authority": "LOCAL_OS",
  "externalUTC": "UNVERIFIED"
}
```

`policySha256` hashes the JSON projection containing `scope`, `authority`, `externalUTC`,
`policyId`, `certificate`, `sourceAuthority`, `maximumBracketMs`, and
`maximumPairingDeviationMs`, in that property order. The operator authorization pins that hash.
The source-local clock uses its own per-boundary certificates; they never qualify as V.
Per-market J preserves the original frame hash used by opens/closes. Joint J preserves the canonical
frame-set hash used by account observations. They share one actual copied-source boundary.
Financial hooks retain the original before-effect boundary and first commit acknowledgement;
subsequent queries do not replace lost acknowledgements.

The one-shot database claim prevents a new process from adopting an earlier run or inventing a
monotonic-clock bridge. PostgreSQL compatibility checks retain the complete send/receive RTT and
are separate from the financial clock supplied to accounting.

## Future local resources

The financial bundle freezes the following nonmonetary envelope:

```json
{
  "artifactLimitBytes": 68719476736,
  "minimumFreeBytes": 85899345920,
  "terminalHeadroomBytes": 268435456
}
```

These are 64 GiB of artifacts, 80 GiB free before start, and 256 MiB reserved **within** the artifact
ceiling for terminal publication. They apply only to the future 28-day comparison. The public
24-hour check retains its separate 16 GiB / 20 GiB limits. They do not increase USD/model budgets
and do not guarantee arbitrary future provider payloads fit; exhaustion fails closed.

Every original first/revised candle and public HTTP body is retained. A prepared packet changes
only when its content changes. Repeated original candle-version objects use ordered references to
previously stored exact records; offline verification expands those references and checks the
original prepared JSON hash. Later observations cannot repair an absent earlier reference. Price
copies refer to prepared packets instead of duplicating complete histories every minute.

Execution keeps compact current state. A separate read-only report worker pages canonical records,
uses one database connection, and requests artifact bytes from the host before every write. During
execution, verified report generations refer to immutable original journal prefixes by hash;
current/previous derived generations are retained. Explicit audit export into a new directory
copies those original prefixes to make a portable packet. No original journal is deleted.

## Implemented future commands

The following are documentation examples for a **later explicitly authorized operator**, not
commands run by this delivery. Execute from `apps/agent-service` with Node 22.22 or newer:

```sh
node --import tsx -- src/evaluate.ts run --config FROZEN_SPEC --env-file DEDICATED_DATABASE_FILE --acceptance FUTURE_AUTHORITY --output NEW_RUN_DIRECTORY
node --import tsx -- src/evaluate.ts status --config FROZEN_SPEC --env-file DEDICATED_DATABASE_FILE
node --import tsx -- src/evaluate.ts stop --config FROZEN_SPEC --env-file DEDICATED_DATABASE_FILE
node --import tsx -- src/evaluate.ts report --config FROZEN_SPEC --env-file DEDICATED_DATABASE_FILE --output NEW_REPORT_DIRECTORY
node --import tsx -- src/evaluate.ts audit-export --config FROZEN_SPEC --env-file DEDICATED_DATABASE_FILE --output NEW_AUDIT_DIRECTORY
node --import tsx -- src/evaluate.ts audit --state FINANCIAL_AUDIT_MANIFEST --output NEW_OFFLINE_DIRECTORY
node --import tsx -- src/evaluate.ts replay --state FINANCIAL_AUDIT_MANIFEST --output NEW_OFFLINE_DIRECTORY
```

Only a dedicated loopback `DATABASE_URL` file is accepted. Model, Exa, trading, and signing
credentials are never loaded. The future run creates C/S/L accounts only after the separate bundle
passes; N and P_context never acquire accounts.

`stop` permanently closes admissions cooperatively; it does not claim flatness or kill authorized
risk reduction and funding work. Status does not assert process liveness. Unknown effects keep
reserves/liabilities and global new-admission barriers. Ownership or persistence failures abort
without recovery. Missed original slots/minutes are recorded and never replayed.

The serialized host services priority minute valuations while waiting for candle preparation.
Funding fetches are independent and never awaited merely to decide. A final refresh can only
cancel; crossing a candle boundary cannot promote an initial hold. Admissions stop after 28 days,
reductions stop at the fixed additional four hours, and funding reconciliation ends after the
additional 72 hours. Pending positions, funding, missing confirmations, and missing original
source evidence remain explicit.

Reports show native gross realized P&L, signed fees, funding, net completeness, exact pending AUSD
reservations, N, L, contextual PTS, original Q memberships, coverage and concentration. Earlier
failed Q cannot be rescued by a later final source or close. Historical emergency evidence remains
visible after a day reset. Zero models/tokens/API USD remain separate from virtual AUSD accounting.
