01TL;DR

Resumen ejecutivo

Que navegar en Pickler se sienta como en iOS: el gesto de «atrás» desliza la pantalla siguiendo el dedo y descubre la anterior, entrar a una pantalla anima desde la derecha, cada pestaña guarda su propia pila y la tab bar tiene una pastilla lima que se arrastra sin despegar el dedo y selecciona al soltar. Se logra migrando la navegación a react-navigation nativa (native-stack + bottom-tabs) sin cambiar la API de las pantallas. Dos fases: F1 migra la navegación (árbol, adaptador Screen → ruta, Page con cabecera/refresh/sello, store sólo con datos, gate de cuenta, push); F2 pone la pastilla arrastrable en la tab bar. Decisiones D1–D12 en el spec.

03Decisiones clave

Decisión Por qué
D1 · native-stack dentro de bottom-tabs, una pila por pestaña (elegido sobre «una sola pila»)Cada pestaña recuerda dónde estaba (vuelves a Markets y sigue en BTC), como las apps iOS nativas; el gesto, el adelante y el ← son los del sistema, sin código de animación propio.
D2 · Las pantallas conservan ctx.nav / back / requireAccount; un adaptador traduce Screen → rutaLas 10 pantallas y DevControls casi no se tocan; la reescritura se concentra en App.tsx, Shell y el store.
D3 · El store deja de guardar screen/stack/nextDos fuentes de verdad para la pila se desincronizan; react-navigation es la dueña y el store guarda sólo datos (mercado, pill, celda de Ask…).
D6 · Cabecera propia dentro de Page (headerShown: false), con fondo opacoLa cabecera viaja con la página en el gesto (el ← se va con la pantalla que sale, como en la captura de Proflores); el fondo opaco tapa la página de abajo.
D8 · Sólo el gesto nativo (PanResponder y ui/gestures.ts se eliminan); cambiar de pestaña no anima; tocar la activa hace popToTopEs el comportamiento estándar de iOS; menos código propio que mantener.
D10 · Un push o «Market desde Wallet» apila Market sobre Markets (salta de pestaña)Con pilas por pestaña, Market pertenece a Markets; sustituye el «Wallet debajo» del fix gate (aprobado en el brainstorm).
D11 · Pastilla que sigue el dedo y selecciona al soltar (no en vivo)Como la tab bar de iOS 26; cambiar en vivo montaría y desmontaría Markets/Wallet varias veces en un solo gesto.

Rulings en ejecución

  1. PF1 — AppCtxProvider/useAppCtx van en src/navigation/context.tsx (nuevo, sin imports de la app salvo el tipo AppCtx); Page.tsx, TabBar.tsx y Navigator.tsx importan de ahí. Rompe el ciclo Page ↔ Navigator del plan. Coste si está mal: un archivo más de 12 líneas.
  2. PF2 — Tasks 3 y 4 se despachan en lote a un solo implementador (módulos pequeños, sin archivos compartidos, código completo en el plan) con una sola revisión del diff conjunto. Coste si está mal: una revisión algo más larga.
  3. R1 (Task 3+4) — useRefreshSeal pasa al patrón contador+efecto del Shell original: onRefreshDone(screen) sólo incrementa done = { n, screen }; un efecto sobre done evalúa refreshOk(done.screen, errors) con los errores de ESE render, sella o marca failed = screen y arma el timeout de 3 s con cleanup. Coste si está mal (junto con R2): un sello de Markets fechado antes de entrar a Markets (semántica igual o mejor que P5).
  4. R2 (Task 3+4) — labelFor es puro; el sello inicial lo pone un efecto del propio hook sobre REFRESHABLE (const nueva en store.ts, que Page también usa) cuando hasData(s) pasa a true por primera vez — ya no hay setState en render. Coste si está mal: ver R1.
  5. R3 (Task 3+4) — el efecto del sello inicial añade address a sus deps y se declara después del efecto de reset (el orden de efectos es el orden de declaración): al cambiar de cuenta, el reset limpia y el efecto re-sella si hay dato (mismo comportamiento que el Shell original, que re-sellaba sobre datos aún viejos). Coste si está mal: un sello con la hora del cambio de cuenta sobre saldos de la cuenta anterior durante <1 s (paridad con lo que había).
  6. R4 (Task 6, para Task 7) — el gesto desde el borde no se puede disparar sintéticamente (Maestro/idb); para la captura a medio camino se usa fullScreenGestureEnabled: true como cambio temporal NO commiteado (revertido antes del commit de Task 8) y se anota en el audit; la prueba real del borde queda para el iPhone. Coste si está mal: la captura muestra el mismo efecto visual con otro punto de inicio del gesto.
  7. R5 (Task 6, corrige P3 del plan) — en ref.ts, navigateTo(screen) para pantallas de pestaña usa navigationRef.navigate("Tabs", { screen: tab, params: nested }, { pop: true }) con nested = { screen, pop: true } para raíces y { screen, initial: false, pop: true } para no-raíces (así Market se apila sobre Markets aunque la pestaña se monte por primera vez — D10 — y volver a una ruta existente hace pop). Nuevo switchTab(tab) en ref.ts = navigate("Tabs", { screen: tab }) sin params anidados (sólo enfoca, conserva la pila); AppStore gana switchTab(tab) con gate; TabBar llama switchTab, no requireAccount. Coste si está mal: media ronda más; sin alternativa (la semántica v7 está verificada en el fuente).
  8. R6 (Task 7) — un intento más con xcrun simctl io <UDID> recordVideo + swipe rápido (que sí hace pop con animación) y tap market-BTC, extrayendo frames con ffmpeg; si tampoco, quedan como residuales para el iPhone. Coste si está mal: ~10 min.
  9. R7 (revisión final, una sola ola de fixes) — __tests__/navigation.test.ts nuevo (StackRouter real de @react-navigation/routers + forma exacta de las órdenes de ref.ts con un ref simulado); Navigator.tsx gana backBehavior="none" (evita que goBackIfCan() salte a MarketsTab desde la raíz de otra pestaña); comentarios corregidos en TabBar.tsx (native-stack, no bottom-tabs), ctx.ts y comingSoonCopy.ts; spec D1/D5 con la ruta signin en minúscula y el detalle real de finishSignin (sin popTo). npm test → 32 suites / 239 tests (+7); tsc limpio. Coste si está mal: una ronda más de fix.
