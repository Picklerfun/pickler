# Perpl paper runtime for studio agents (v1)

Status: decided autonomously on 2026-10-03 (the owner asked for no questions and is away). It
narrows `perpl-agent-runtime-v1.md` to what a studio agent needs now, and builds on code already on
main: agent advice (#81, #84), the perps paper simulator (migrations 0012/0013), the Perpl data
plugin and transport, the perps study's proposal contract (#80), and the live studio (PR #86, on
which this branch is based: `config.risk`, `config.entry`, the live and draft studios).

## 1. Problem and users

A studio agent with `config.perpl` can be created, funded and published, and then does nothing:
the research runner only knows Polymarket (`run-research.ts` needs a market selection, so
`assertCanQueue` refuses with `CATEGORIES_REQUIRED`), the perps paper simulator is operator-only
and pinned to one config version, and the live studio draws Positions, Decisions, Record, the
strip and "Waiting on you" as empty. This spec makes a Perpl agent decide on its own, on paper,
inside its caps, and shows it.

Users: the agent's owner (studio), and later the public record (out of scope here).

## 3. User flows

1. **Owner publishes** an agent → within the hour its first check runs; the strip shows "Checked BTC, ETH · entry 1 held · 0.9s", Decisions gets a row, nothing opens unless every entry line is met and conviction ≥ 0.55.
2. **Entry in approve mode** → "Waiting on you" on Overview with the canvas's card (what it puts in, notional, risk at stop / gain at target, the why lines) and Enter / Skip; expires in 15 minutes.
3. **Entry in auto** → a paper position appears in Positions with stop, target and time stop; Overview's "Its positions" shows it; stats and meters move.
4. **Exit** → the exits job closes at stop, target or time; Decisions logs `exited` with P&L; Record updates.
5. **Pause entries** → checks still run and log, but no `entered` (outcome `held` "PAUSED"); exits keep firing. **Stop · close all** → closes everything on paper and pauses.
6. **Draft Console** → "Run it on paper" → steps stream into "What it did" (polling) → the outcome card; a trade appears under Trades.

## 4. API (all `/v1/studio`, owner JWT; reads for workspace members, writes owner-only)

| Method | Path                                      | Notes                                                                                                                                                                 |
| ------ | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/agents/:id/perps/checks`                | Manual check; `Idempotency-Key`; 202 `{ checkId }`; 409 `NOT_A_PERPL_AGENT`, `RUNTIME_DISABLED`, `CHECK_RUNNING`; 429 `MANUAL_LIMIT` (6/day)                          |
| GET    | `/agents/:id/perps/checks`                | `?before=&kind=` newest first, 50 per page: id, at, trigger, outcome, outcome text, instrument, action, probability, horizon, entries/exits/never lines, inputs, cost |
| GET    | `/perps/checks/:id`                       | one check with its steps (for "What it did" polling)                                                                                                                  |
| GET    | `/agents/:id/perps/positions`             | open (with mark from the board, unrealized P&L, stop/target/time, liquidation estimate) and closed (newest 50)                                                        |
| POST   | `/perps/positions/:id/close`              | owner close; 409 `POSITION_CLOSED`                                                                                                                                    |
| POST   | `/agents/:id/perps/stop`                  | close all + pause                                                                                                                                                     |
| GET    | `/agents/:id/perps/proposals`             | pending                                                                                                                                                               |
| POST   | `/perps/proposals/:id/approve` \| `/skip` | 409 `PROPOSAL_EXPIRED`, `PROPOSAL_DECIDED`, caps codes                                                                                                                |
| GET    | `/agents/:id/perps/record`                | R13 stats + equity series + today's new margin, realized today, open count, leverage in use, checks today, cost today                                                 |

Every route is described for OpenAPI. The research worker gets two internal jobs (no HTTP): the hourly due-check dispatcher and the exits job, both on the existing minute Cron, plus a Queue message `{ kind: "perps-check", checkId }`.

## 5. Data model

Migration `0027_perps_checks` (after 0026): `pickler.perps_checks`, `pickler.perps_proposals`, the six columns on `pickler.perps_paper_positions`, indexes on (agent, started desc) and (status, expires_at) and (exit_due_at) where open. Grants follow 0013's runtime tables. No product-schema change.

## 6. Integrations

Perpl REST through the existing transport (its 12-request session cap raised to 24 for checks of two instruments with web); the market board for marks; the configured model provider; Exa. No new secret.

## 7. Design work

All drawn: live canvas (Overview "Waiting on you", Positions, Record, Decisions, strip, Controls meters and health) and draft canvas (Console "Run it on paper", "What it did", Trades). Staged states add populated fixtures: `perpl-live-active` (positions + proposal), `perpl-decisions-active`, `perpl-record-active`, `draft-console-ran`. Position and equity charts use the existing `@pickler/ui` chart where it fits; otherwise the SVG sparkline.

## 8. Security and abuse

Owner-only writes; checks never use the delegated signer or real funds; model output cannot size or leave Perpl's paper account; manual checks rate-limited; global ceiling; admissions off by default.

## 9. Acceptance criteria and tests

1. Core: `decideOutcome` table-tested over R6's order (never, entries, conviction, each cap, free equity, each entry mode, close, hold, paused).
2. Sizing (R7) and exits (R10) pure tests; day-loss (R11).
3. Postgres: check rows, proposals lifecycle (pending → approved/skipped/expired), product paper account across config versions, exits job closes at stop/target/time exactly once, stop-all.
4. Runtime: a check end to end with fake Perpl data and a fake model (entered, held, blocked, failed).
5. Routes: each code; owner-only writes.
6. Web: models for feed rows, proposal card, positions, record, strip, meters; staged states pass the design harness.

## 10. Rollout

Migration 0027 before the API and research worker. `PERPL_RUNTIME_ENABLED=true` on research and API when an operator opens it; testnet first (`config.perpl.network`).

## 11. Out of scope

Live trading (`perpl-live-v1.md`), posts, the Console chat, decision review (accept/reject the call quality), Brier scoring and public record, Jev routing, websockets.
