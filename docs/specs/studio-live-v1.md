# Studio: the live studio of a published Perpl agent (v1)

Status: decided autonomously on 2026-10-02 and revised on 2026-10-03 against the final canvas (the
owner asked for no questions). Canvas: Claude Design project
`c03aadb4-7bb2-429e-aa49-98ae4218bc1f`, `Pickler Studio v5 Live.dc.html` (final: live strip,
Record, Console, Controls, Marketplace, Wallets and Account sections). Builds on
`studio-draft-dashboard-v1.md` (the draft studio, Connect X, Go Public) and keeps its rule D19: no
copy promises what the Perpl runtime will do.

## 1. Problem and users

After Go Public a Perpl agent stops being a draft, and the studio drops it into the old home and
rail, which were built for Polymarket agents: their Brief edits `config.profile`, their Run now is
refused (`CATEGORIES_REQUIRED`), their schedule can never unlock. Nothing there fits a Perpl agent.

The canvas draws the whole studio of a live agent: what it just did, approvals, positions, its
record, decisions, a console thread, posts, the build sections split into Limits and Controls, the
marketplace (agents, markets, leaderboard) inside the studio, the wallets, and the account. Most of
the agent's own activity is the Perpl runtime and live trading, which are not built
(`perpl-agent-runtime-v1.md`, `perpl-live-v1.md`). This spec builds the studio and everything that
has real data today, and draws the rest as empty or Soon states that say what is true. Later specs
fill them (§11).

Users: a studio account that owns a published agent created by the simplified flow (`config.perpl`).

## 3. User flows

1. **Go Public** (draft studio) → the live Overview. Header: avatar, name,
   `@HANDLE · PERPL · MONAD · PUBLIC SINCE {MON D} · DAY {n} · {SECTION}`, "Pause entries", and
   "Stop · close all" shut. Four stat tiles; the banner when something needs fixing; the live strip
   above everything.
2. Each section per §2. Saving follows the draft studio: buttons shut unless dirty and valid,
   "Saving…", a stale version (409 `CONFLICT`) reloads and says "It changed somewhere else.
   Reloaded.", previews send nothing.
3. **Pause entries** flips the chip to "PAUSED · EXITS ONLY" and the button to "Resume"; a failure
   shows inline and changes nothing.

## 4. API

Built: `PUT /v1/studio/agents/:id/setup` (any Perpl agent; `caps.maxOpenPositions?`,
`caps.dayLossStopAusd?`, `entry?`; writes a version row) and `GET /v1/studio/agents/:id/versions`.
Everything else the studio reads already exists: `PUT /pause`, `PUT /identity`, the X routes,
`/wallets`, `/wallets/ledger`, the transfer routes, `GET /v1/marketplace/markets`,
`/markets/:symbol`, `/directory`, `/leaderboard`, `GET /v1/signing/passkeys` and the add-passkey
routes, and the account profile routes the account page uses. No other new route.

## 5. Data model

Built: migration `0026_setup_versions` (`agents.setup_versions`), and `config.risk` /
`config.entry` in core and the strict `agentConfigSchema`.

## 6. Integrations

None new.

## 7. Design work

All drawn in the final `Pickler Studio v5 Live.dc.html`. Staged states (`?stage=`, never in
production): `perpl-live` (Overview), `perpl-paused`, `perpl-warnings`, `perpl-positions`,
`perpl-record`, `perpl-decisions`, `perpl-console`, `perpl-posts`, `perpl-brief`,
`perpl-brief-dirty`, `perpl-sources`, `perpl-limits`, `perpl-controls`, `perpl-identity`,
`perpl-agents`, `perpl-markets`, `perpl-leaders`, `perpl-wallets`, `perpl-account`,
`perpl-account-profile`, `perpl-account-notify`. Each is a design-harness route proving
`#live-section-<key>` (or the banner, the paused chip, the dirty note, the account tab). Position
and equity charts come with the data they draw.

## 8. Security and abuse

- `PUT /setup` stays owner-only, versioned, bounded by core; a public agent's handle and X account
  cannot be changed here.
- The studio adds no signing path: transfers and passkeys use the existing ceremonies.
- External links (docs, community, support) open with `rel="noopener noreferrer"`.

## 9. Acceptance criteria and tests

1. A published agent with `config.perpl` opens the live studio; a draft opens the draft studio; an
   agent without `config.perpl` opens the legacy one (pure model test).
2. Built and tested: `reviseSetup`, risk and entry bounds, the mirror test, setup versions.
3. Web models (rail, status, strip, tiles, warnings, health, meters, mode notes, caps, markets,
   directory cards, leaderboard rows, wallet cards, account rows, version rows) are unit-tested;
   every staged state passes the design harness with 0 FAIL.
4. The draft studio's tests and staged states still pass with the shared shell.

## 10. Rollout

Migration 0026 is additive and goes before the API (after main's 0025). Nothing else to configure.

## 11. Out of scope, and the specs that follow

1. **Perpl paper runtime for studio agents** (`perpl-agent-runtime-v1.md`): the strip, decisions
   with their steps and per-decision questions, paper positions, the record, real stats and meters.
2. **Approval flow and enforcement:** proposals, `entry` and `risk` enforced, auto-pause, owner
   notifications (the Account tab's toggles).
3. **Posts:** on Pickler, mirrored to X (`go-public-v1.md` D7–D8).
4. **Live trading** (`perpl-live-v1.md`): "Close now · passkey", "Stop · close all", signed caps,
   Markets' Trade.
5. **Console** ("Talk to it"), AI credits, paid reads (Ask), token backing, sessions, profile
   visibility toggles, X feeds and open-interest plugins.
