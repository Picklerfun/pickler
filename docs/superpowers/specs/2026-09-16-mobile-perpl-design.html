App móvil Pickler — Fase 2: trading manual en Perpl (pestaña Trade)

Fecha: 2026-09-16 Estado: aprobado por Jesús (diseño en chat), pendiente de plan Slug: mobile-perpl Rama: feat/mobile-perpl, base main (2d928fc, merge de feat/mobile-wallet) Contexto: el bounty exige "executes trades through Perpl". El equipo decidió el 2026-09-16 que el venue es Perpl (Polymarket sale), que el perp lo operan tanto una persona como un agente, y que se empieza por el manual. Esta fase es ese manual. Verificación previa contra la testnet: docs/investigacion/perpl.md (cuenta #619, API key, WS y orden real).

TL;DR

Una pestaña nueva Trade donde el usuario, con su cuenta de Mera y su AUSD:

  1. Habilita trading (una vez): approve + createAccount(≥100 AUSD) +

    2. allowOrderForwarding(true) + registro de una API key Ed25519 firmada con la wallet.

  2. Ve saldo de trading, mercados (precio de marca y cambio 24h) y posiciones

    3. con PnL y precio de liquidación.

  3. Abre un perp (Long/Short, monto en AUSD, 1x–5x) con orden de mercado por WebSocket,

    4. y lo cierra completo.

  4. Mueve fondos entre la wallet y la cuenta de trading (Add funds ≥10, Withdraw).

Sin backend. Todo firma en el teléfono: secp256k1 (sesión de Mera / viem) para las tx y el EIP-712; Ed25519 (@noble/curves, ya en node_modules vía viem) para la API key.

Todo lo nuevo en apps/mobile/src/perpl/ es puro (sin react-native ni expo-constants; solo fetch, WebSocket global de RN y viem/noble), testeable en Jest.

2.3 perpl/onboarding.ts

Calldata puro + envío con la sesión de Mera, mismo patrón que wallet/chain.ts:

readAccountId(address): Promise<bigint>            // getAccountByAddr; revert → 0n

Cada send* usa maxPriorityFeePerGas explícito (20 gwei) para que un reintento reemplace una tx descartada (lección del spike).

2.4 perpl/apiKey.ts

generateTradingKey(): { privateKey: Uint8Array; publicKeyHex: Hex }        // ed25519 de @noble/curves
wsSigninCanonical(chainId, timestampMs, nonce): string                              // 4 campos
signWsSignin(privateKey, chainId): { timestamp; nonce; signature }                  // base64url sin padding
normalizeTypedData(typed_data): TypedDataDefinition   // quita EIP712Domain de types; chainId y message.time de hex a bigint

Errores de enroll con significado: 404 → "Create the trading account first" (orden de pasos); 409 → generar otro par; 423 → "Too many trading keys; revoke one at testnet.perpl.xyz/apikeys".

2.6 perpl/ws.ts

class TradingSocket (sin React):

  • connect({ apiKey, privateKey, onEvent }) → abre, manda mt: 29 como primer frame, arranca ping.
  • Estado interno: status: "connecting" | "live" | "reconnecting" | "closed", head, lfr,

    • account, orders: Map<oid, Order>, positions: Map<pid, Position>, pending: Map<sn, PendingOrder>.

  • placeOrder(frame) → asigna sn, rq = max(lfr, lastRq) + 1, lb = head + ttl; devuelve

    • Promise<OrderOutcome> que resuelve con el primer mt: 24 no-fallo para ese rq (o el primer fallo si solo hay fallos), rechaza si mt: 3 code ≠ 0, y resuelve unknown a los 30 s. Un sr: 32 reintenta una vez con rq nuevo.

  • Parsers puros exportados: parseFrame(json), applyFrame(state, frame) (para tests con

    • fixtures del spike).

  • Reconexión: backoff hasta 30 s; al reconectar, snapshots frescos reemplazan el estado;

    • pendientes sin resolver pasan a unknown. Dos 3401 seguidos → evento keyRejected.

2.7 storage/perpl.ts

pickler.perpl.v1 (SecureStore, WHEN_UNLOCKED_THIS_DEVICE_ONLY, sin requireAuthentication): { accountId: string; apiKey: string; privateKey: base64url }. loadTradingKey, saveTradingKey, clearTradingKey (se llama desde signOut junto a clearStoredAccount). Entrada malformada → se borra y se lee como ausente (misma regla que storage.ts).

type PerplState =

  live: { status; account; positions: Position[]; orders: Order[] } | null;
  enable(amount: bigint): Promise<void>;      // pasos 1–4, reanudable

Reglas: enable verifica antes de cada paso (readAccountId, readAllowance, fw del snapshot o getAccountByAddr + reintento, loadTradingKey) y nunca repite createAccount si ya hay id. 3. Pantallas

3.1 Trade — sin cuenta (state.status === "none")

Tarjeta: "Enable trading" / "Moves AUSD from your wallet into a Perpl trading account. One Face ID, four steps." Campo de monto (default = minAccountOpen, validación ≥ mínimo y ≤ AUSD en wallet; sin MON → mensaje del faucet). Botón Enable trading. Durante onboarding: lista de 4 pasos con check/spinner/error (Approve AUSD · Create trading account · Allow one-click trading · Register trading key) y botón Retry en el paso fallido. Debajo, MARKETS en modo solo lectura (precios) para que la pestaña no esté vacía.

3.2 Trade — listo

  • Tarjeta "Trading balance": formatAusd(b) grande; línea "formatAusd(lb) locked in

    • positions · formatAusd(b − lb) free"; chip de conexión ("Live" lima / "Reconnecting…" ámbar / "Offline" gris).

  • Botones Add funds (→ perpsFunds, fundsMode: "add") y Withdraw to wallet ("withdraw").
  • MARKETS: fila por mercado: símbolo + nombre, precio de marca formateado, cambio 24h

    • (mark − prev)/prev con signo y color; tap → perpsMarket.

  • POSITIONS: vacío → "No open positions. Pick a market above."; fila: LONG/SHORT (tag

    • lima/rojo), "size symbol · lvx", entrada → marca, PnL no realizado (signo, color), "Liq. est. price", botón Close.

3.3 Mercado → orden (perpsMarket)

Segmento Long / Short. Monto en AUSD (TextInput decimal-pad, Max = libre). Selector 1x · 2x · 3x · 5x. Tarjeta resumen: "Size ≈ N symbol", "Est. price mark", "Fee ≈ fee AUSD", "Liquidation est. price" (resaltado si lv > 1, con "Higher leverage means a closer liquidation price."). Validación: monto > 0, ≤ libre, tamaño > 0. Botón Review → tarjeta de confirmación → Confirm long/short → estados: Sent ("Order accepted — waiting for the fill", spinner) → Filled ("Filled fs symbol at fp · fee f AUSD", botón "Back to Trade") / Failed (razón de describeOrderStatus, botones "Edit" y "Back") / Unknown a los 30 s ("No confirmation yet. Check your positions.").

3.4 Close

Desde la fila de posición: hoja de confirmación "Close size symbol LONG at market · Est. PnL ±x AUSD" → Close position → mismos estados que 3.3 con copy de cierre ("Closed · realised ±x AUSD").

3.5 Trading funds (perpsFunds)

Cabecera con los dos saldos (Wallet formatAusd(treasury.ausd) · Trading free). Monto con Max; validación por modo (add: ≥ minDeposit, ≤ wallet; withdraw: ≥ minWithdraw, ≤ free). Review → Confirm → Face ID si locked → "Sent: 0x…" → "Confirmed" y ambos saldos refrescados. Add funds hace approve solo si la allowance es insuficiente.

3.6 Wallet

Bajo "Available to spend" se añade la línea "formatAusd(b) AUSD in trading · Trade tab" cuando perpl.state.status === "ready" (si el socket no está vivo, se muestra el último valor conocido con "· last seen"). Nada más cambia en Wallet.

4. Estado y datos

  • PerplState sale de storage/perpl.ts al arrancar (loading → none/ready), en

    • paralelo con useAccount; ready no implica socket abierto.

  • usePerpl.setActive(true) cuando S.screen ∈ {perps, perpsMarket, perpsFunds}; el hook

    • abre el socket y el polling de context; false los cierra (con 2 s de gracia para navegaciones internas).

  • Órdenes en vuelo: TradingSocket.pending por sn; la pantalla espera la promesa.
  • Sign out: clearTradingKey(), socket cerrado, state = none. Cambio de cuenta (otra

    • passkey): la key guardada pertenece a otra address → se detecta (address guardada ≠ actual) y se trata como none.

  • AppCtx gana perpl: Perpl.

6. Pruebas

Unitarias (Jest), contra el defecto:

  • wsSigninCanonical con vector fijo; firma Ed25519 verificable con la pública; base64url

    • sin padding.

  • normalizeTypedData con el typed_data real del spike (chainId 0x279f → 10143n, time hex → bigint).
  • parseContext con el JSON real de testnet (mercado 64: pd 5, sd 0, ttl 20, mm 500, taker 345).
  • sizeFromAusd (11.1 AUSD a 1x con mark 2220 → 500 MON; BTC con sd 5), takerFee

    • (11.1 AUSD × 345 micros → 3830), liquidationPrice (long 1x ≈ 0.05×entry; 5x ≈ 0.85×entry).

  • orderFrame/closeFrame: rq = lfr + 1, lb = head + ttl, t 3/4 según lado, p: 0, fl: 4.
  • applyFrame con los frames reales del spike: mt: 19 (cuenta 619, lfr), mt: 24

    • filled (st: 4, sr: 43), failed (st: 7, sr: 32), mt: 27 apertura y cierre, mt: 21 actualiza lfr y saldo.

  • describeOrderStatus para 32/34/35/43/44 y desconocido.
  • Onboarding: máquina de pasos con mocks de readAccountId/readAllowance/loadTradingKey

    • — reanuda en el paso correcto y nunca llama createAccount dos veces.

  • Store: GATED, SHOW_TABS, CAN_BACK, headerFor para las tres pantallas nuevas.

npx tsc --noEmit limpio y npm test completo.

Manual en simulador (cuenta nueva o la del simulador 0xe371…, fondeada desde la KAT): Enable trading con 100 AUSD (4 pasos, Face ID) → long 1x de 10 AUSD en MON → Filled → posición con PnL → Close → Add funds 10 → Withdraw 5 → Wallet muestra "in trading". 7. Fuera de alcance

Agente como operador delegado y caps (F3); órdenes límite, TP/SL, cierre parcial; historial de fills (REST firmado); conectar Market/Portfolio/Trade-de-tokens a Perpl; token/launchpad; mainnet (URLs y contrato cambian; la key en SecureStore sin gate se revisa); Android.
