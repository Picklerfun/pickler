App móvil Pickler — Fase 1: passkey + tesorería AUSD

Fecha: 2026-09-15 Estado: aprobado por Jesús (diseño en chat), pendiente de plan Slug: mobile-fase1 Contexto: bounty Best Mobile Trading App on Monad (Agora) del hackathon Monad Metropolis — $10,000, deadline 13 oct 2026 21:59 CST.

TL;DR

Se construye la app móvil de Pickler en React Native / Expo (no Swift: ver §1). La fase 1 entrega login con passkey vía Mera → cuenta EVM en Monad Testnet → pantalla con balance de AUSD y MON → botón de faucet de AUSD, con build firmado listo para TestFlight. Sin backend, sin VPS.

Lo que el bounty exige y esta fase no cubre (Perpl, trade) queda en §9 como fases siguientes.

2. Alcance

Entra

  1. Crear cuenta con passkey (Face ID) o iniciar sesión con una existente.
  2. Derivar la cuenta EVM con Mera; mostrar la dirección.
  3. Leer y mostrar balance de AUSD y de MON en Monad Testnet.
  4. Botón Get test AUSD: tx al faucet de Agora firmada con la llave derivada.
  5. Lock (cierra sesión de firma, conserva cuenta) y Sign out (borra cuenta

    6. del dispositivo; no borra el passkey del llavero).

  6. Sitio estático en pickler.fun con /.well-known/apple-app-site-association.
  7. Build firmado y subido a TestFlight.

No entra

Agentes, launchpad/token, Perpl, harness, backend, mainnet, Android, onramp real de AUSD, recuperación de cuenta (export de seed).

5. Flujo y estado

Arranque
  └─ leer address (sin gate)
       ├─ no hay  → Welcome
       └─ hay     → Home (balances cargan sin pedir Face ID)

Welcome
  ├─ Create account → mera.createPasskey(rpId) → PRF → cuenta
  └─ Sign in        → mera.signIn(rpId)        → PRF → cuenta
       └─ guardar address (sin gate) + prfOutput (gate biométrico) → Home

Home
  ├─ address (copiar)
  ├─ AUSD balance  ← balanceOf(address) en 0xa9012a…22dC
  ├─ MON balance   ← getBalance(address)
  ├─ Get test AUSD → leer prfOutput (Face ID) → derivar cuenta → requestFunds(address)
  │                  → mostrar hash + link explorer → refrescar balances
  ├─ Lock          → olvidar prfOutput en memoria
  └─ Sign out      → borrar address + prfOutput de SecureStore → Welcome

Estado en memoria: { address, signer? }. signer existe solo entre desbloqueo y Lock. No hay estado global más allá de un contexto de React.

7. Infra y Apple

Cloudflare (cuenta Pickler): proyecto Pages pickler-passkeys con public/.well-known/apple-app-site-association:

{ "webcredentials": { "apps": ["2PBQJ37Q8W.fun.pickler.app"] } }

Custom domain pickler.fun → Pages crea el registro DNS y el certificado. Requisito de Apple: Content-Type: application/json, HTTPS, sin redirect. Cuando exista la landing real se sirve desde el mismo proyecto; el archivo no cambia.

Apple: App ID fun.pickler.app con capability Associated Domains (webcredentials:pickler.fun), registrado por el build de device con -allowProvisioningUpdates. App en App Store Connect creada a mano por Jesús (pasos en el plan). Archive → upload → TestFlight, con el flujo de proflores-ios-release como referencia.
