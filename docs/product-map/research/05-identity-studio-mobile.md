# 05 — Identity, custody, the studio, the product hosts, Mera and the mobile marketplace

Research note for the product scope map. Read-only; worktree `pickler-turnkey`, branch
`codex/product-scope-map` = `origin/main` at `c407fec`. Probes of the live site were plain HTTPS
GETs (and one empty POST) on 2026-09-30 ~07:04 UTC.

## 1. Summary

1. Identity and custody are built and tested on main: email/Google OTP signup → a required passkey that creates the Turnkey sub-organization and master wallet → handle. After that come agent wallets with three DENY policies and a delegated user, AUSD deposits signed by the passkey, and SIWE wallet sign-in for the marketplace. None of this has run against real Turnkey, a real chain deposit or a real browser wallet session.
2. The studio works end to end on paper. There are two ways to create an agent: `/studio/new`, which runs the wallet ceremony and a first run, and the brief on the empty home, which does a preview run and then saves a private draft with no wallet. Go Public (voice, connect X, the wallet with the brief's caps as policies, funding), forking a ranked agent, and the Sources, Identity, Profile, Audience and Token sections are all "Soon" with no backend behind them.
3. The three-host split in `product-hosts-v1.md` is **not implemented**. `hosts.ts` still knows only two products, with marketplace = `pickler.fun` and studio = `app.pickler.fun` (`hosts.ts:10-13`). There is no landing product, no host rule for the AASA file, no `applinks`, and no `hrefFor`. The spec's plan to gate the AASA file in middleware cannot work as written, because Workers Assets serves `public/` before the worker runs.
4. Mera is the passkey wallet (a PRF-derived EOA). The owner rule (§7) puts it on the whole marketplace, web and phone, with an EOA as a web-only alternative. Main offers only the EOA on the web. On the web its PRF signer was removed (PR #64). No Mera code is left except `wallet_links.kind='mera'`, which nothing ever writes. The React Native app exists, is on TestFlight as bundle `2PBQJ37Q8W.fun.pickler.app` (PR #31), and today trusts `pickler.fun`. It is not in any repo in the Picklerfun org and not in this monorepo.
5. Production (`pickler.fun`, served by the `pickler-web-staging` worker) is behind main and partly broken. `app.` and `studio.pickler.fun` have no DNS records. The deployed API predates the console→studio rename, and `/v1/signing` and `/v1/auth/wallet` return 404 there (not mounted). `/agents`, `/leaderboard` and `/markets` return 500. According to PR #61, migrations 0000–0022 are applied. Still pending: `TURNKEY_RPID`, email confirmations, and the Hyperdrive role's access to `auth.users`.

## 3. Gaps

1. **The host split is only half done, and the defaults are wrong for the target.** `hosts.ts:11-12` falls back to marketplace `pickler.fun` and studio `app.pickler.fun`. If the target is deployed without the three `NEXT_PUBLIC_*_HOST` build values, the studio ends up on the host that is meant for the marketplace and for Mera's RP. That is exactly the shared-picker situation product-hosts-v1 §3 exists to prevent. There is no landing product.
2. **The AASA host rule cannot be implemented in middleware** while the file sits in `public/` and Workers Assets serves it first. One of these has to change: move it to a route handler with `run_worker_first` for `/.well-known/*`, serve it per host from a separate asset, or gate it with Cloudflare rules. Until then, adding `studio.pickler.fun` to the same worker associates the iOS app with the Turnkey RP.

## 7. Against the owner's wallet rule (added 2026-09-30)

**The rule:** Turnkey is for the **studio only**. The **marketplace** (web and mobile app) uses **Mera** on
both surfaces. An **EOA** (injected, such as MetaMask) is an alternative on the **web marketplace only**.
The mobile app has no EOA.

### 7.2 Code and specs that contradict the rule

1. **`product-hosts-v1.md` §1 table (line 24), §2 (lines 65-72) and §7 "Mera on the web" (line 247).** These say the web marketplace takes an injected EOA and Mera is phone-only. They give a reason: a PRF-derived key in a web page sits in memory next to every script and extension. The rule puts Mera on the web as the primary wallet. The spec needs revising, and the owner should explicitly accept the key-in-page risk, or ask for a mitigation such as a short-lived session, clearing the key after use, or strict CSP.
2. **`apps/web/AGENTS.md:78` ("The wallet").** It says "Nothing in this app derives or holds a private key, and no new signer may", and it says "the person's own Pickler wallet … is custodied in Turnkey". Both conflict with the rule. The first forbids Mera on the web. The second treats the Turnkey master wallet as the person's wallet on the marketplace side. Under the rule, the Turnkey master wallet is the studio's funding pot, and the marketplace wallet is Mera or an EOA.
3. **`apps/web/src/features/wallet/lib/signer.ts:9-11`.** The same claim appears in code comments ("The person's own Pickler wallet … is custodied in Turnkey"), and `SignerKind` has only `"injected"`.
4. **`turnkey-passkey-custody-v1.md` §6, "The PRF signer is retired".** It says "Turnkey becomes the only custody path; `connect` keeps only the injected browser wallet". The reason for retiring it was that Mera and Turnkey **shared the RP `pickler.fun`**. The three-host split removes that reason (Mera's RP becomes `app.pickler.fun` and Turnkey's becomes `studio.pickler.fun`). That section should record that the retirement was about the shared host, not a ban on Mera.
5. **`apps/web/src/server/hosts.ts:12` (studio falls back to `app.pickler.fun`).** This is the hard blocker for web Mera. As long as the studio, and therefore Turnkey enrolment, can land on `app.pickler.fun`, a Mera passkey on that RP would appear in Turnkey's picker. Reintroducing Mera on the web has to come after the host cutover (S1) and `TURNKEY_RPID=studio.pickler.fun`.
6. **`docs/market/token-launch.md` product-split table.** It says token traders sign with "Mera in the app, or an external wallet". Under the rule it should read Mera on the app and the web, with an external wallet on the web only.
7. **`user-profiles-and-products-v1.md` §3 example** ("Mera on their phone and MetaMask on their laptop") is consistent with the rule, but §13 "What this means for the plan" says "the marketplace can ship on EOAs and add [Mera] without revisiting anything". Under the rule Mera is the primary wallet, not a later second connector. Its §5 already matches the rule (Mera for the marketplace on web and phone).

### 7.3 What is missing to satisfy the rule

- **Web Mera connector** (spec + build). A second `SignerKind` (`"mera"`) behind `signer.ts`, calling the SDK directly (`getPasskeyPrfOutput`/`createSecp256k1SigningSession` → `toViemAccount().signMessage`) for the SIWE message. wagmi is not needed (user-profiles §13). `rpId` must be **`app.pickler.fun`**, the same value as the phone, and the key model must be the same on both. The PRF model is deterministic per credential and RP, so it gives the same account on web and phone. The vault model does not carry across devices. It also needs the error and screen for a passkey that has no PRF, such as a local Chrome profile, Bitwarden or Dashlane, per user-profiles §13; the natural fallback is "use a browser wallet instead". It also needs a session lifetime and key-clearing policy.
- **`kind` on verify/link** so `wallet_links.kind='mera'` gets written, and the account sheet's wallets section (product-hosts §5) can tell a person which wallet is which.
- **Mobile:** the four `app.pickler.fun` values (product-hosts §4) in the app, plus S2. S2 should state that the phone offers **Mera only**: no EOA, no WalletConnect.
- **Doc updates** for items 1–4 and 6 in §7.2, made in the same change that reintroduces web Mera.

This changes the scope of S1 and S2 in §4. S1 must land before any web Mera work. S2 should say "Mera only". Add **S9: `marketplace-mera-web-v1`** (the connector above). It depends on S1, the owner accepting the key-in-page risk (or naming a mitigation), and confirmation of which key model the phone app uses (open question 1).
