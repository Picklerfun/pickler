# 03 — Launchpad, agent tokens and the indexer

Research record, untracked. Read against `codex/product-scope-map` = `origin/main` at `c407fec`
on 2026-09-30. Static reading only: nothing was built, run, deployed or signed.

## 1. Summary

1. The contracts are complete for v1 and tested offline (107 tests) and on a Monad testnet fork (11 tests). None is deployed anywhere, and `contracts/script/` holds only `.gitkeep`. There are no deploy scripts, no Pickler address in `packages/chain`, and no chosen licence (`UNLICENSED`).
2. On `main` the indexer only runs the raw-log half. The worker reads one factory address, never runs the projector, and never sees curve, adapter, escrow or V4 logs, so `market.tokens` and `market.trades` would stay empty even with a deployed factory. PR #37's description says integration fixes landed, but the commits `fcfe750..6463181` are dangling objects and not in `main`.
3. The API serves only reads (`/v1/launches`, `/:id`, `/:id/trades`). Nothing quotes, prepares, submits or reconciles a launch or a trade. The `launch.*` tables (drafts, presets, metadata, transaction requests) have no writer, and the outbox has no producer or consumer.
4. Nobody can create a token from the product. The studio's Token section is "Soon". No use case maps an agent to an `agentKey`. The factory lets any creator claim any `agentKey` first, which is a squatting bug. Nothing composes the master wallet (Turnkey passkey) with `createLaunch`.
5. Buyers can connect an injected wallet on `/tokens/[ticker]`, but the trade button is permanently disabled. The ticket prices in MON while the preset's quote is AUSD, and its math is illustrative. Mera has been removed from the web: the product's passkey wallet is now Turnkey, and `docs/market/token-launch.md` is stale on this point.

## 3. Gaps

**Deploying the launchpad contract requires all of the following, and none is in place:**

1. **A network and venue decision.** 10143 has no official Uniswap V4. The choices are mainnet-only graduation, our own V4, or the Monad-maintained V4 (`uniswap-v4-spike.md:29-35`). The fee tier was measured only at 1% with spacing 200.
2. **Economic preset numbers** (supply, sale/LP split, virtual reserves, fees, protocol share, LP creator share, launch fee) and confirmation that AUSD `0xa9012a05…22dC` is the testnet quote (`networks.ts:71-73`). Spec §11 lists these as open.
3. **A licence** in place of `UNLICENSED`, plus a threat model and an independent review before any real funds are involved (spec §9 last paragraph).
4. **A Foundry deploy script** that follows the fixed order: `FeeEscrow(treasury)` → `GraduationAdapterV4(poolManager, positionManager, stateView, permit2, lockerFeeRecipient)` (deploys the locker) → `CurveDeployer(adapter, escrow)` → `LaunchFactory(operator, curveDeployer)` → `escrow.initialize(factory, locker)` (`contracts/AGENTS.md` "Deployment order"). Then `publishPreset` from the operator. Each external address must be checked against its `codeHash` in `deployments.ts`.
5. **Key custody for three roles that do not exist yet**: the deployer EOA, which also performs the one-time `escrow.initialize`; the factory `operator`, an immutable address that can publish presets and suspend launches forever, so it should be a multisig or a Turnkey-held key, not a laptop key; and the treasury / locker fee recipient addresses. None is named anywhere in the repo.
6. **Explorer verification** (Monad explorer / Sourcify) and **recording** in `packages/chain/src/deployments.ts`: chain ID, address, deployment block, `abiHash`, `codeHash`, contract version.
7. **Indexer configuration**: Hyperdrive id in `workers/indexer/wrangler.jsonc`, `LAUNCH_FACTORY_ADDRESS` and `LAUNCH_FACTORY_DEPLOYMENT_BLOCK` (the start block is the factory's deploy block, never "now"), a trustworthy `RPC_URLS` (currently the public `testnet-rpc.monad.xyz`), and a measured `CONFIRMATIONS` (5 is a guess, spec §11 "Finality policy").
8. **Staging DB** migrated through 0016, with `service_role` grants.

**Letting an owner create a token end to end is also blocked:**

- **Contract bug**: `agentKey` is not bound to the creator (`PicklerLaunchFactory.sol:152-157,258-276`). It needs a derivation such as `keccak256(creator, agentId)` enforced on chain, or a Pickler-signed authorization, plus a failing impersonation test. Until this is fixed, "one canonical token per agent" is not guaranteed.
- **No product↔chain binding**: nothing stores `agentKey` for an agent, `market.tokens` has no `agent_key` column, and the projector writes `agentId: null`. The owner's launch cannot be attributed to their agent, and `/tokens/[ticker]` 404s for unlinked tokens.
- **No launch use case** in `packages/core/src/features/launch` beyond indexing and curve math. There are no draft → validated → prepared → submitted → launched transitions, even though the enum exists at `0015:3`. No metadata upload or pinning (image, description, URI plus content hash). No preset selection. No mirror of presets from `PresetPublished` into `launch.presets`.
- **No signing path**. The launchpad spec picked an injected wallet for v1 (§1 point 2). Since then the product's own wallet is the Turnkey master wallet with passkey root. Nothing builds a `createLaunch` transaction for Turnkey the way `deposit-tx.ts` does for transfers. The creator/fee recipient identity (master wallet? an external wallet?) is also undecided.
- **No quote/prepare/register/reconcile API** and no `transaction_requests` writer. Idempotency-Key handling (spec §6 B6) is unbuilt.
- **Launch fee is never charged**, although the preset carries it.

**Indexing completeness (the catalogue stays empty even after deployment):**

- The worker never runs the projector. The PR #37 fix that did this (`a7e533c`, "runConfiguredPass … projector.project") is **not on main**: `git merge-base --is-ancestor 6463181 origin/main` fails. It also never discovers curves, so it never sees `CurveBought`/`CurveSold`, and it misses the graduation adapter, escrow, `Transfer` for holders, and V4 swaps by `poolId`.
- There are no candles, holders or fee-payout projections, which `marketplace-real-data-v1.md:53` expects. There is no automatic unwinding of projections on reorg, no concurrency fencing, and freshness is not per stream (PR #62 §5 "Indexer and public truth").
- There is no metadata reader composed for the projector. Name, symbol and decimals come from token calls, and the image must come from the metadata URI, which is not emitted.

**Trading the token (marketplace):**

- There is no quote route, even though the spec says quotes are on-chain via `eth_call` and refused when state is stale.
- There is no AUSD approve step (the curve pulls by `transferFrom`) and no permit or EIP-3009 path, though AUSD supports both (`networks.ts`).
- Post-graduation trading would need a V4 swap route (Universal Router or PoolManager unlock) that no code builds.
- The trade panel labels amounts in MON and uses a fake depth constant.
- Whether buyers can use their Pickler (Turnkey) master wallet or only an injected wallet is unspecified. Mera is gone.

## 4. Specs to write

1. **Launch identity and authorization (`launch-authorization-v1`).** Defines how a product agent becomes an `agentKey`, for example `keccak256(abi.encode(creator, agentUuid))` checked on chain, or a Pickler-signed EIP-712 grant verified by the factory. Covers who the `creator` and `creatorFeeRecipient` are (master wallet vs external wallet), the nonce and deadline policy, the contract change plus impersonation and replay tests, the new `market.tokens.agent_key` column and how the projector links `agent_id`, and what happens to the ticker when a launch fails. Depends on the owner deciding whether launches are permissionless or Pickler-gated. Blocks every other launch spec.
2. **Launchpad deployment and network manifest (`launchpad-deployment-v1`).** Covers the Foundry script in `contracts/script/`, the order, parameters per network, the testnet V4 choice, the key custody of deployer, operator, treasury and locker fee recipient, explorer verification, recording in `packages/chain/src/deployments.ts`, the `publishPreset` ceremony, the licence, and a runbook including `setLaunchesEnabled(false)`. It also carries the acceptance checklist before mainnet (review, threat model, finality measurement). Depends on the approved preset numbers (LP-01) and spec 1's contract change.
3. **Indexer completeness (`launch-indexer-v2`).** Covers multi-emitter streams (factory, then each curve from its creation block, adapter, escrow, token `Transfer`, PoolManager by `poolId` from the graduation block), composing the projector in the worker (recovering the dangling `fcfe750..6463181` work or redoing it), holders, candles, fee payouts, automatic projection rollback on reorg, cron concurrency fencing, per-stream freshness and a measured finality policy, and staging configuration (Hyperdrive, vars). Acceptance is PR #62 §6 journey 6. Depends on spec 2 for addresses and start blocks.
4. **Studio token launch (`studio-token-launch-v1`).** Covers the owner flow behind the "Token" section: eligibility (public agent? minimum record?), ticker reservation, name, symbol, image and description, metadata storage and content hash, preset display (supply, curve, fees, graduation target, irreversible LP lock), the `launch.drafts` state machine `draft → validated → prepared → submitted → launched | abandoned`, the passkey-stamped Turnkey signature of `createLaunch` (mirroring the deposit prepare/confirm), `transaction_requests` with Idempotency-Key, receipt-based reconciliation (a receipt, not a hash, is the truth) and recovery from revert, timeout or reorg. It also covers the API routes and DTOs, and the relationship with PR #61 private drafts ("Go Public"). Depends on specs 1–3.
5. **Token trading (`token-trading-v1`).** Covers the buyer flow on `/tokens/[ticker]`: which wallets (injected, the Turnkey master wallet, a future passkey library), AUSD approve or permit, on-chain quote routes that refuse on stale state, the confirmation contents from spec §6 B7, buy/sell exact-in/exact-out and the `ExceedsRemainingSupply` remainder, a `graduation_pending` state and a permissionless "finalize graduation" action, post-graduation V4 swaps, fee claims for creators, reading `/v1/launches/:id` instead of the agent profile, and fixing unlinked-token 404s. Depends on specs 2–3, and on spec 1 for attribution.
6. **Launchpad product specification in the repo.** "Pickler — Launchpad en Monad" (LP-01..LP-22), which `launchpad-monad-v1.md:5` treats as the authority on rules, is not in the repository. Commit it, or an English summary of it, so that economic rules, fees, anti-snipe and MEV posture have a reviewable source. There are no dependencies.

## 5. Open questions for the owner

1. Is launching **Pickler-gated** (only agents we authorize, as `token-launch.md:25` says) or **permissionless** (as the factory now allows)? This decides the fix for the `agentKey` squatting bug.
2. Which wallet is the **creator** and the fee recipient: the owner's Turnkey master wallet (passkey), an external wallet, or either? Should the agent wallet ever hold or trade its own token? Its policies currently forbid `approve`.
3. Which **testnet V4 venue** should we use (spike options 1–3), and which fee tier?
4. What are the **preset numbers** and the launch fee (currently declared and never charged), and is AUSD the quote asset on both networks?
5. Who holds the **operator** key, which can publish presets and suspend launches forever, and who holds the treasury key? Should either be a multisig?
6. When may an owner launch? Only a public agent, only after N settled picks, or anytime (PR #62 §8)? Is the ticker reserved at agent approval or at launch?
7. Should buyers use the **Pickler passkey wallet** (Turnkey) or only injected wallets? Is Mera still on the roadmap, for example for iOS?
8. The **PR #37 integration fixes** (`fcfe750..6463181`: worker projector, curve discovery, atomic projection, pagination) are not on main. Were they intentionally dropped, or should they be recovered?
9. May the public catalogue show a token with **no linked agent**, as the projector now produces? If so, what should its detail page show?
10. Which licence do the contracts get?
