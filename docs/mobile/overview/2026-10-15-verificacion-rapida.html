01TL;DR

Development stays incremental; distribution stays clean

A deterministic native fingerprint decides whether Pickler can reuse its installed development client. JavaScript-only work uses Metro without prebuild or Xcode. Native inputs force a rebuild. Phase closure and release become separate gates, and every path reports cache state and time by stage.

02Roadmap

The approved design defines two phases. Detailed tasks will be added only when each phase receives its own implementation plan.

F1

Runner, native fingerprint, and timings

Establish the four-level command contract, calculate an inspectable fingerprint of native-sensitive inputs, route application-only changes away from native builds, and record stage durations plus cache state.

04Key decisions

DecisionWhy
Fail closed on native driftA stale client cannot produce accepted visual evidence.
Fingerprint explicit native inputsThe mobile dependency closure, sanitized resolved Expo config, plugins, embedded assets, and toolchains remain inspectable; generated iOS/Pods/build outputs stay excluded.
Measure each stage and cache outcomeThe report identifies the expensive operation instead of hiding it in one total.
Keep release cleanDevelopment speed must not reduce archive reproducibility or signing confidence.
Require a physical iPhone for real Face IDThe simulator cannot prove the real biometric prompt or hardware-backed behavior.
