Feature

La misma cuenta que en la web username obligatorio

Con la wallet desbloqueada, la app entra sola a la API del producto y, si la cuenta no tiene username, lo pide sin dejar saltarlo. Apagado mientras no se configure PICKLER_API_URL.

Qué cambió

  • La app entra a la API del producto con la wallet: pide el mensaje, lo firma con la llave ya abierta (sin Face ID extra) y lo presenta con kind: "mera". Es la misma cuenta que en la web.
  • Si el servidor dice que la cuenta no tiene username, una pantalla tapa la app: se elige uno o se cierra sesión. Mismas palabras que el paso de la web.
  • Quien ya tiene cuenta bajo su wallet de navegador vincula este passkey en pickler.fun; la pantalla lo explica, abre la web y vuelve a comprobar.
  • El @username aparece en la pestaña Wallet. Al cerrar sesión se borra el guardado.
  • Sólo la respuesta del servidor retiene a alguien: API sin configurar, caída o con error no bloquea a nadie.
  • Sin dependencias nuevas; el token vive en memoria y sólo se guarda { address, handle }.

Por qué

La web ya entra con la wallet y exige username (PR #74), y la app deriva la misma dirección del mismo passkey, pero no hablaba con la API: no tenía sesión ni username. Juvenal pidió el 2026-10-02 que la app use la misma cuenta y que el username sea obligatorio, con el mismo flujo que la web. Spec: docs/mobile/superpowers/specs/2026-10-02-mobile-account-design.md.
