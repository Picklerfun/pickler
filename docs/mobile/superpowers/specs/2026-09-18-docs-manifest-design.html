Sistema de documentación con manifest (modelo Proflores) — design spec

Fecha: 2026-09-18. Estado: aprobado en brainstorming; pendiente el plan de F1. Origen: proflores-monorepo (docs/overview/, docs/superpowers/, scripts/agent-infra/, .agents/skills/proflores-{retomar,overview-new,dev-new}), estado medido el 2026-09-18.

1. Visión

Hoy el estado de Pickler vive repartido en cinco sitios que no se leen entre sí: la tabla del roadmap (docs/04-roadmap-bounty.md), el "Estado" del README (desactualizado: dice fase 1 cuando fase 2 ya está en TestFlight), cuatro handoffs (docs/05..08), la memoria de Claude y git. Ninguno es máquina-legible; retomar una sesión exige leerlos todos.

Se adopta completo el modelo de Proflores: un manifest (docs/overview/data/manifest.js) como registro de proyectos con fases, un dashboard (index.html) que lo consume, un overview HTML por sub-proyecto, dev trackers para cambios de un PR, spec + plan en Markdown con HTML vecino autogenerado, un audit por fase ejecutada, tooling que valida que todo eso coincida, y tres skills (retomar, overview-new, dev-new) que lo operan.

5. Skills

Las tres se adaptan de las de Proflores conservando estructura, comandos y anti-patterns; cambian rutas, marca y ejemplos. Específico de pickler-retomar, además de manifest, git (branches.mjs) y audits:

  1. Deadline del bounty (13 oct 2026 21:59 CST) y días restantes, calculados con date.
  2. Estado del build de TestFlight: del dev tracker testflight-* más reciente del manifest.
  3. Cuentas de testnet (simulador, KAT, cuentas Perpl): sección "Estado de las cuentas" del

    4. audit más reciente que la tenga.

Son las tres cosas que en Pickler se pierden entre sesiones y no están en git.
